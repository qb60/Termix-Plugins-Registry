# Модель доверия

Администратор Termix доверяет **одному public key**, сверяя его fingerprint при Add registry. Реестр проверяет Ed25519 подпись SHA-256 скачанного архива тем же ключом. Схема индекса сама по себе не доказывает подпись; обе проверки обязательны. Индекс не подписывается отдельно: HTTPS, pinned key, подпись каждого package и проверяемый manifest ограничивают подмену.

Публикация private key равносильна возможности выпускать доверенные плагины. Он хранится только у владельца и в secrets plugin repositories. У registry workflow приватного ключа нет. Не запускайте release workflow для непроверенного кода: доступ к signing secret предполагает доверие к `main`, maintainers и dependencies. Не передавайте secret PR workflows из forks. Включите защиту main и review изменений workflow при командной работе.

Реестр не запускает содержимое `.tmxplug`. Архив обрабатывается в памяти с ограничением сжатого и распакованного размеров. Ссылки, особые файлы, опасные пути, дубликаты, неверный tar checksum и отсутствующие entry points отклоняются. Проверяются точное происхождение release asset URL, tag, ID, version, capabilities, bytes/hash/size и подпись. Token GitHub API не отправляется на release download URL. Пакеты заведомо доверенного автора всё равно являются исполняемым кодом: криптография подтверждает автора и целостность, а не отсутствие ошибок.

Проверка существующих versions и владельца ID использует предыдущий Pages index. После первого deployment это защищает от незаметной замены подписанного файла или смены ID тем же source repository. После удаления Pages или HTTP 404 генератор не может доказать историю: восстановите доверенный previous index перед повторной публикацией. Для более строгого контроля храните offline-backup индекса и release artifacts. Невозможно сохранить доступность пакета, если его GitHub assets удалены; по умолчанию такой sync останавливается.

Правила индексирования намеренно строже official sync: неподписанный asset и замена опубликованного hash завершают весь запуск ошибкой. Предыдущий Pages deployment продолжает работать. Official reserved IDs обновляются при каждом sync; если официальный источник недоступен, новое состояние не публикуется. Manifest validator и JSON schema зафиксированы версиями SDK/файла — их обновление требует review и тестов.

При компрометации: остановите публикацию, отзовите доступ к plugin repositories и соответствующие tokens, удалите скомпрометированные secrets, уведомите пользователей, сравните assets с доверенными hashes, создайте новый ключ **локально** и следуйте процедуре ротации SIGNING. Termix не принимает смену registry key автоматически. Переустановка доверия и плагинов требует участия администратора; автоматической миграции здесь нет.

В tests ключи создаются только в памяти на время запуска. Демонстрационные artifacts, полученные `npm run fixture`, подписаны временным тестовым ключом и непригодны для production доверия; private key не записывается. В репозитории не должно быть `.key`, `.env` и private PEM. Public `registry.pub` допустим и должен коммититься после настройки.
