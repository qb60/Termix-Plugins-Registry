# Диагностика и восстановление

Сначала откройте GitHub → Actions → нужный run → красный job → упавший step. Не публикуйте ключи вместе с логами. Сбой build/sync оставляет предыдущий Pages deployment нетронутым.

| Ошибка                                   | Действие                                                                                                                                                                                                                                                             |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `registry.pub` отсутствует               | Скопируйте только public key из keygen, запустите configure и commit public file.                                                                                                                                                                                    |
| Нет signed releases                      | Сначала выполните Release в plugin repository и проверьте оба assets. Не создавайте вручную index с placeholders.                                                                                                                                                    |
| Signature mismatch                       | Скачайте архив и `.sig` одной версии. Выполните CLI verify с registry public key. Убедитесь, что secret содержит содержимое правильного private key. Пересоберите новую версию; опубликованный файл не заменяйте.                                                    |
| Manifest/tag/repository mismatch         | Исправьте исходный manifest и workflow плагина, согласуйте `vX.Y.Z`/имя файла и выпустите следующую версию.                                                                                                                                                          |
| Reserved/duplicate ID                    | Используйте собственный ID в новом плагине; удалите ошибочный source из конфигурации. Официальный ID нельзя перекрывать.                                                                                                                                             |
| Published artifact replaced              | Восстановите исходные байты архива и подпись из надёжной копии с тем же SHA-256. Новое содержимое публикуйте под новой версией.                                                                                                                                      |
| Previously published release disappeared | Восстановите прежний release/tag и оба assets с прежним hash. При намеренном снятии всего плагина явно удалите repository из plugins.json; удаление единственного плагина не публикует пустой index — сначала решите судьбу registry у пользователей.                |
| HTTP 403/429                             | Проверьте GitHub rate limit, статус GitHub, наличие стандартного `GITHUB_TOKEN` в sync step; повторите позже. Не расширяйте права без причины.                                                                                                                       |
| SDK не знает capability                  | Обновите pinned SDK осознанно, выполните npm install, тесты и сохраните lockfile.                                                                                                                                                                                    |
| Pages HTTP 404                           | Settings → Pages → Source: GitHub Actions; проверьте успешный deploy job и environment github-pages. Открывайте точный путь `/Termix-Plugins-Registry/index.json` с верным регистром. Первый run без релизов не создаёт deployment. Подождите распространения Pages. |
| deploy permission denied                 | Разрешите Actions в Settings → Actions → General; проверьте pages/id-token permissions workflow и правила environment/организации.                                                                                                                                   |
| Termix не видит новую версию             | Подождите до 15 минут, обновите Plugins, проверьте engine ranges, `gated`, beta channel и registry происхождения установленного плагина.                                                                                                                             |
| Key changed                              | Не подтверждайте случайный ключ. Сверьте fingerprint у владельца; для реальной ротации нужен отдельный план SIGNING/SECURITY.                                                                                                                                        |

После исправления: Actions → Sync and deploy registry → Run workflow → main, либо Re-run failed jobs, если конфигурация этого commit уже корректна. После изменения файлов запускайте новый run на новом commit, а не старый run со старой конфигурацией.

Скачайте последний рабочий `index.json` и храните его backup вне Pages. При потере deployment восстановите `state/index.json` из доверенной копии для локальной диагностики. Не используйте недоверенный индекс для снятия проверки неизменяемости. Сам генератор пишет `public/index.json` атомарно только после проверки всех источников; workflow загружает artifact только после успешной валидации.

## Ошибочный release, который ещё не был проиндексирован

Публикация исправленной следующей версии сама по себе не скрывает старый некорректный release: sync проверяет всю историю. Если предыдущий рабочий index **никогда не содержал** отвергнутую версию, исправьте её detached signature для тех же проверенных bytes либо вручную снимите ошибочный release с публикации/удалите его `.tmxplug` asset. Release без пакета пропускается. После этого выпустите исправление новой версией и повторите sync. Если версия уже была в доверенном index, снимать её или заменять bytes нельзя без отдельного плана: восстановите исходные bytes и подпись из backup. Это различие позволяет убрать впервые опубликованный ошибочный пакет, сохраняя защиту уже установленной истории.
